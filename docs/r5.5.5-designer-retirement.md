## 2. Canonical Designer route

`/p/:projectId/workspace/designer`. It is the route produced by
`WorkspaceModeSwitcher` (`onModeChange` -> `goProject(pid, 'workspace', mode)`)
and by `App.tsx` `workspaceActive`/`normalizeWorkspaceMode`. The Designer
surface receives project identity, role, document identity, canonical document,
lifecycle and live revision through the existing workspace architecture
(`ProjectWorkspaceShell` -> `DesignerMode` -> `Designer`). No second canonical
route is created.

## 4. `designer/apply` status and decision

Reconfirmed consumers after R5.5.2:

- MCP tool `designer_apply` (`apps/api/src/mcp/server.ts:659-680`) calls
  `DesignerService.apply` directly. This is an intentional public contract.
- No web source calls the HTTP route; `Designer.test.tsx` pins that the
  unified workspace Designer never POSTs to `.../designer/apply`.

Decision: **retain** the endpoint and `DesignerService.apply` as legacy
compatibility infrastructure for MCP. The unified workspace Designer does not
call it (proposals go through the shared mutation pipeline).

## 6. DesignPackage decision

**Retain `DesignPackage` as a portable artifact contract, not live document
state.** Evidence: it is a self-contained, versioned, validated envelope with
export/import and media-stripping semantics, but no runtime producer or consumer
in the platform. The separation is:

```
CanonicalDocument = live workspace truth
DesignerProposal  = temporary, revision-bound proposed change (one run)
DesignPackage     = portable/shareable design artifact (export/import)
```

It is explicitly **not** the canonical workspace document and **not** a second
live document representation; nothing in the workspace/session/document model
may depend on it. Intended future boundary: design export/import, templates,
sharing, reusable page designs and external agent exchange. No persistence,
routes, UI, conversion pipeline or runtime state are added in this milestone.

## 7. Final Designer ownership model

| Concern | Owner |
| --- | --- |
| One Designer surface | `ProjectWorkspaceShell` designer mode -> `DesignerMode` -> `Designer` |
| One document source | Workspace session (canonical document) |
| One document identity | Workspace session (`session.identity.documentId`) |
| One revision | Workspace document revision (`documentRevisionOf`) |
| One mutation path | Shared mutation pipeline (`CompositionApplyBridge` + `EditorContext`) |
| One run lifecycle | `useDesignerRunController` (Designer + embedded agent) |
| Designer API | `/designer/runs` (durable); `execute`/`intent`/`apply` retained as server/MCP APIs |
| DesignPackage | `@seo/contracts` portable artifact only (no runtime owner) |

## 8. Retained compatibility surfaces

1. `/p/:projectId/designer` -> deterministic redirect to
   `/p/:projectId/workspace/designer` (`replaceState`, no second render).
2. `POST /content/:id/designer/apply` + `DesignerService.apply` -> legacy
   compatibility API for MCP `designer_apply`.
3. `/designer/execute`, `/designer/intent` -> server API retained; not consumed
   by the web UI.
4. `DesignPackage` -> retained portable contract with no runtime integration.
