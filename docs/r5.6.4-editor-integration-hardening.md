## 1. Scope

Confirm the seams R5.6.2/R5.6.3 touched - document switch, mode switch, editor
state, contextual rail state and the Composer/Designer handoff - and confirm the
mutation bridge preserves identity, revision, autosave and undo. Fix a concrete
defect only if one is found; otherwise strengthen tests and record verified
behaviour.

## 2. Result

**No concrete integration defect was found.** The shared session, selection
owner, mutation bridge, autosave/revision and mode dispatch behave as the recon
described. The two items the recon already recorded as minor (G7 selection reset
keyed on `documentId`; the rail tab reset when the on-demand Tools surface is
toggled off) remain benign and deferred; neither is a correctness defect.

## 3. Behaviours verified (and now pinned)

Seams reviewed: `ProjectWorkspaceShell` (mode dispatch, document-scoped
`preview`/`railOpen`/`toolsOpen`), `EditorMode` (`assistantOpen`, keymap),
`EditorView` (inline AI reset on `session.boundary`, `initialContentId`
one-shot), `EditorWorkspace` (`data-tools-open`, on-demand rail),
`IntelligenceRail` (document-scoped tab, identity-keyed `IntelligencePanel`),
`ContentToolbar`/`ContextualToolbar`, `CompositionApplyBridge` (boundary +
`targetDocumentId` + revision guards), `EditorContext` (`setContent` mutation
paths), `useDocumentSession`/`useAutosave`.

Confirmed, with evidence:

- **UI-only state does not mutate the document.** Tools/Preview/Insert toggles,
  the rail tab and outline selection only change scoped UI state or the editor
  selection; autosave and revision read only the document/metadata fields.
- **Document-scoped UI resets on a switch.** `preview`/`railOpen`/`toolsOpen`
  (shell) and the rail tab resolve through `useDocumentScopedState`, whose scope
  key (`documentScopeKey`) advances only on a successful transition. A late
  setter captured under the previous scope can never write to the live scope.
- **Mode switching mounts exactly one body** and drops editor infrastructure
  when leaving the editor (`ProjectWorkspaceShell.isolation.test.tsx`).
- **The mutation bridge applies through the single editor transaction path.**
  The applied composed page/operation batch is one undoable (and redoable)
  history step, emits exactly one document update (so the existing autosave
  boundary persists it), and is applied at most once per staged value even across
  context re-renders.
- **Identity/revision guards hold.** A moved boundary, a foreign
  `targetDocumentId`, or a stale `baseRevision` refuses the apply and leaves the
  editor untouched.
- **A following handoff is handled.** A second, distinct staged mutation after
  the first is applied against the document as it now stands.

## 5. Intentionally unreachable

The "staged while the editor is already mounted" variant is unreachable by
construction: staging only happens in Composer/Designer, which unmount the
editor (one mode body renders at a time), so the bridge always runs after the
editor remounts. The bridge-level case (a live editor at mount) is the normal
path and is covered by the existing and new tests. No shell-level test is added
for the unreachable variant.

## 6. Deferred (unchanged)

- G7: `EditorSelectionProvider` clears on `documentId` rather than `boundary`,
  so a first-save id adoption clears the canonical selection once. Transient and
  self-healing (the next selection event re-derives it); recorded, not scheduled.
- Rail tab resets when Tools is closed and reopened. Expected for an on-demand
  surface; no state is lost that the user set for the current document.
- `popstate` back/forward special handling (route limitation, unchanged).

## 7. Architecture

No new identity, session, provider, editor instance, revision, autosave,
selection owner, route or contract. No change to the mutation funnel, the run
controller or the mode dispatch. R5.6 scope is unchanged; R5.7/R5.8 remain the
next product surface.
