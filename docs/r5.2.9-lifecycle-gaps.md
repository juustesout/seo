# R5.2.9 - Adoption-stable document boundary and inline AI identity guard

Status: **implemented**. Closes the two material gaps found by the R5.2.8 recon
(`docs/r5.2.8-final-hardening-recon.md`). No new identity, epoch or state owner
is introduced; both fixes reuse the owners R5.2 already established.

## 1. G1 - Adopting a new document's id is not a document boundary

Before: `adoptDocumentId` advanced the persistent identity (`new` -> a server id)
without advancing `generation`. Both the editor key and the workspace scope were
recomputed from `documentScopeKey(identity, generation)`, so the id token moved
from `new#N` to `<id>#N`. On the first autosave of a new document that:

- remounted `RichTextEditor` (fresh undo history, lost cursor/selection and
  scroll position);
- remounted `EditorWorkspace` and reset its document-scoped UI state;
- flipped `editingId`, so `useDocumentLoad` refetched and `documentLifecycle`
  reported `loading` until it settled, flashing the loading screen and
  re-seeding the workspace from the server.

After: the session owns a frozen `boundary` key alongside `generation`. Both
advance together, only when `runBarrier` reports `switched`:

- `useDocumentSession.ts`: `boundary` state (`INITIAL_BOUNDARY`) is set with
  `documentScopeKey(next, nextGeneration)` inside `runBarrier`; `adoptDocumentId`
  changes only `identity`; `discardDocument` resets identity and sets a fresh
  boundary from the current generation. `documentScopeKey` is now documented as
  the transition-key constructor, not a live value.
- `Content.tsx`: `WorkspaceStateProvider documentKey={session.boundary}` and
  `writing.editorKey={session.boundary}`.
- `useDocumentLoad.ts`: new `adopt(documentId, data?)` marks the persisted id as
  already loaded and reports it `ready` without a fetch. `Content.commit` calls
  `session.adoptDocumentId(row.id)` and `detail.adopt(row.id)` together. The
  adoption marker is cleared as soon as the requested id moves away, so a later
  genuine switch back to that id loads normally (never adopted-empty state);
  `reload()` still forces a fetch.

`editorHistoryKey` is retained (delegates to `documentScopeKey`) for callers that
need to construct a transition key; the two live consumers now use the frozen
`session.boundary`.

## 2. G2 - Legacy inline AI is identity-guarded

Before: `runAi`/`runAiEdit` awaited the API and then unconditionally wrote
`aiSuggestion`/`aiEditProposal`. A response that landed after the user switched
documents repopulated the panel against the new document, and `applyAi`/
`applyAiEdit` mutated the active editor.

After: a small guard hook captures the live session boundary for one operation:

- `session/useOperationBoundary.ts` (`useOperationBoundary(boundary)`) returns a
  `begin()` that captures the current `boundary` and yields `{ isStale }`. It
  wraps the existing boundary rather than adding a second identity/epoch,
  mirroring `useEmbeddedAgent`.
- `Content.tsx`: `runAi`/`runAiEdit` call `beginOperation()` before the request
  and drop a stale success, a stale failure and a stale busy reset
  (`if (!op.isStale()) setBusy(false)`). A late result for A therefore cannot
  populate the panels of B, surface an error on B, clear B's in-flight busy
  state, or mutate B's editor.

The existing `resetAi()` on a successful switch still clears pending AI state;
the guard is what stops a late in-flight response from repopulating it.

## 3. What is not touched

No second document identity, generation, revision, autosave, selection or UI
state owner. The save barrier, autosave, revision model, selection model,
undo/redo boundary, lifecycle projection and routes are unchanged. Browser-exit
and in-app route-unmount protection (R5.2.8 G3) remain deferred to R5.11 or the
R5.3 navigation shell.

## Tests

Added (web 523 -> 536):

- `session/adoptionBoundary.test.tsx` (4): adoption keeps the same editor
  instance and undo history; keeps the frozen boundary and generation; preserves
  document-scoped workspace UI state; does not refetch or enter the loading
  lifecycle.
- `session/operationBoundary.test.tsx` (5): a late response/failure for the
  outgoing document is not promoted; a late response does not clear the active
  document's busy state; a late edit result cannot mutate the active editor; a
  new-document/close transition invalidates an operation even with the guard
  component still mounted.
- `session/useDocumentLoad.test.tsx` (4): loads on id change; `adopt` reports
  ready without a fetch; reopening an adopted id after leaving loads normally;
  `reload` forces a fetch after adoption.
- `session/useDocumentSession.test.ts`: the R5.2.8 `it.fails` marker was
  converted into a passing assertion that adoption keeps `boundary` and
  `generation` stable while exposing the persisted id.
