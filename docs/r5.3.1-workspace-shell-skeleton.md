# R5.3.1 - Three-mode workspace shell skeleton

Status: **delivered**. First slice of R5.3 (`docs/phase-5-roadmap.md:86-118`),
implementing the shell boundary from the locked ADR
(`docs/r5.1-workspace-decisions.md`). This slice moves ownership; it does not yet
unify the Composer/Designer interiors (R5.4/R5.5).

## 1. Goal of this slice

- Introduce the product-level `ProjectWorkspaceShell` that owns the shared
  document session (identity, loader, lifecycle, autosave, live document state)
  for every mode.
- Extract the current `views/Content.tsx` editor orchestration into
  `views/EditorView.tsx`, which consumes the shared session instead of owning
  it.
- Add the canonical route `/p/:projectId/workspace/:mode`
  (`editor | composer | designer`, default `editor`).
- Add `WorkspaceModeSwitcher` (three prominent mode buttons, `aria-pressed`,
  keyboard reachable) that syncs the mode to the URL without a page reload.
- Keep Composer and Designer reachable as compatibility bodies and legacy
  routes.

No behavior change to the editor UI, autosave, revision, selection, undo/redo
or save barrier is intended.

## 2. Ownership after this slice

```text
ProjectWorkspaceShell
  |- useWorkspaceSession (shared)   identity + loader + lifecycle + autosave
  |                                 + live document fields (title/status/doc/
  |                                   keyword/meta/slug/savedAt) + commit
  |- WorkspaceModeSwitcher          editor | composer | designer
  |- WorkspaceSessionProvider       the shared value above
  |- DocumentSessionProvider        the canonical consumer contract (R5.2.2)
  |- WorkspaceStateProvider         document-scoped UI state (R5.2.7)
  `- Active mode
       |- EditorView                (was the body of views/Content.tsx)
       |- Compose                   compatibility body
       `- Designer                  compatibility body
```

The shell owns the session; modes own their tools and local UI state. Inline AI
state stays with `EditorView` (it is editor-specific), guarded by the
`useOperationBoundary` capture of the shared session boundary.

## 3. Deliberate staging (not yet done)

- Composer/Designer are still the legacy standalone views; they do not yet read
  or write the shared live document. R5.4/R5.5 converge them onto the shared
  document and the one write path (ADR Decisions 4 and 5).
- The shell header here is just the mode switcher. Lifting `DocumentHeader` and
  the single save indicator to the shell chrome is a later R5.3 slice; the editor
  keeps its current `DocumentHeader` so this slice does not change editor
  behavior.
- The shared assistant entry is still editor-only (`InlineAssistantSlot` /
  `EmbeddedAgentEntry`); the shell-level entry is deferred.
- Editor selection/undo are preserved across document transitions (R5.2) but a
  mode switch unmounts `EditorView`, so its in-memory undo history is not yet
  preserved across modes. The live document (including unsaved edits) is, because
  it lives in the shell.

## 4. Live-document seeding

To keep the live document authoritative across a mode remount, the session
exposes `seededKey` (the boundary key whose document has been seeded into the
live fields) and `live`. `EditorView` seeds `RichTextEditor` from `live.doc` once
its document has been seeded, and from the loader payload on the first ready
render of a newly opened document. This preserves the current "no stale
document, no mismatch" behavior (R5.2) while allowing the editor to remount
without reverting to the server payload.

## 5. Routing

- Canonical: `/p/:projectId/workspace/:mode` (optional `/…/:contentId`).
- Legacy compatibility entry points: `/p/:id/content[/:contentId]` (editor),
  `/p/:id/compose` (composer), `/p/:id/designer` (designer) render the same
  shell with the mapped mode.
- `Route` gains a second project sub-segment (`sub2`) so the workspace can carry
  both a mode and a document id. The route model (`Route`, `parseRoute`,
  `routePath`) now lives in `apps/web/src/lib/projectRoute.ts` so it is unit
  testable without importing the whole `App`.
- The project sidebar collapses the three creative entries into one `workspace`
  entry, active for both the canonical route and the legacy entry points.

  session boundary, one editor mount), routes a composer draft into the editor

- `lib/projectRoute.test.ts`: `parseRoute`/`routePath` round-trip the canonical
