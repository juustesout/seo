# R5.5.1 - Designer workspace binding

Status: **delivered**. The Designer mode now reads the one shared workspace
document instead of selecting/fetching its own. `Designer` is no longer mounted
as a compatibility body with only a `projectId`/`role`; a new `DesignerMode`
boundary reads `WorkspaceSessionValue` and hands the view the open document's
identity, title, live canonical document and revision. The view performs **no
`/content` list or detail read of its own**.

This milestone is integration only. It adds no document identity, loader,
autosave, history, context or workspace-state provider, and it deliberately does
**not** yet route Designer proposals through the shared mutation pipeline (that
is R5.5.2). The server run endpoint and the existing server-side apply are
unchanged.

## 1. Reconnaissance findings (R5.5.0, confirmed in code)

1. **Mount site.** `ProjectWorkspaceShell` rendered `<Designer projectId role />`
   in the `designer` branch. The view never read the workspace session.
2. **Own document source.** `Designer` fetched its own `/content?limit=300` list
   (selector) and `/content/:id` detail, computed
   `contentRevisionOf(detail.content_json)`, and reviewed/applied against that
   separately fetched stored revision.
3. **Shared owner already existed.** `useWorkspaceSessionContext` already owns
   the authoritative `session.identity.documentId`, the live `doc`, the
   canonical lifecycle and the live `documentRevisionOf(doc)`, and already backs
   Editor and Composer.
4. **Pattern to mirror.** `ComposerMode` is the boundary precedent: it reads the
   shared session and passes focused props to `Compose`, owning no document
   state.
5. **Apply is out of scope.** Apply still goes through
   `POST /content/:contentId/designer/apply` (whole-document
   `ContentService.update` with a server revision re-check). Replacing that is
   R5.5.2.

## 2. What changed

- **New `apps/web/src/workspace/DesignerMode.tsx`** (exported from
  `workspace/index.ts`). It reads `useWorkspaceSessionContext()` and passes to
  the view:
  - `documentId` = `session.identity.documentId` (null when none is open);
  - `documentTitle` = the live workspace title;
  - `documentRevision` = `documentRevisionOf(ws.doc)` (the live concurrency
    token, the same hash the server derives from `content_json`);
  - `documentStatus` = `lifecycle.status` (idle/loading/ready/error);
  - `currentDocument` = `canonicalFromEditorDocument(ws.doc)` or null when the
    live document is not representable.
  It mounts no editor infrastructure, so the R5.3.3 isolation guarantee is
  preserved.
- **`ProjectWorkspaceShell`** mounts `DesignerMode` in the designer branch and
  stops prop-drilling `projectId`/`role` into the (now session-aware) body.
- **`views/Designer.tsx`**:
  - removed the `/content?limit=300` list fetch, the `/content/:id` detail
    fetch, the `<select>` document picker and the `storedCanonical` helper;
  - removed `useAsync`, `asTipDoc`, `contentRevisionOf`,
    `canonicalFromEditorDocument` from the view (moved to the boundary);
  - edit mode targets the **one open document** (`documentId`), shows its live
    title and revision, and gates on `documentStatus === 'ready'`;
  - the review's source document/preview is the **live** `currentDocument`, and
    `revisionMatches` compares `proposal.baseRevision` against the live
    `documentRevision`;
  - added an explicit **foreign-document** state: if a restored/succeeded edit
    run targets a document other than the one now open, it is shown as
    proposal-only with a notice and no apply (this prevents applying proposal A
    to document B, which matters because two empty documents share a revision).

## 3. Document identity matrix (after R5.5.1)

| Concern | Owner | Designer behavior |
| --- | --- | --- |
| Project id | workspace session | read via `DesignerMode` |
| Open document id | `useDocumentSession` | target only, never selected by Designer |
| Document title | workspace live state | display only |
| Canonical current document | workspace live `doc` | preview/diff only |
| Concurrency revision | `documentRevisionOf(ws.doc)` | client guard; server still re-checks on apply |
| Create-flow (no document) | Designer form/run state | unchanged (proposal-only) |
| Run lifecycle/bookmark | `useDesignerRun` | unchanged (convergence is R5.5.4) |
| Apply persistence | server `designer/apply` | unchanged (R5.5.2) |

## 4. What did not change

- No new router, document id, loader, autosave, history, context or
  workspace-state provider.
- No new server route, contract, migration or agent/planner change.
- The create flow (intent anchored to the empty-document revision, never applied)
  is untouched.
- The run client (`useDesignerRun`), its localStorage bookmark and its
  submit/restore/poll semantics are untouched.
- Apply still uses the existing server-side whole-document endpoint; the
  workspace does not yet write the applied proposal into the live document.

## 5. Tests / verification

- `views/Designer.test.tsx` (23): the 15 creation-mode tests are unchanged; the
  edit/apply block was reworked to bind to shared props and now asserts the
  Designer performs **no content list/detail read**, uses the live revision for
  `revisionMatches`, disables apply on a revision mismatch, reports a
  foreign-document proposal as proposal-only, and still cannot apply twice /
  still rejects locally.
- `workspace/DesignerMode.test.tsx` (4, new): the boundary binds to the shared
  open document + live revision, submits against the shared session projectId,
  performs no `/content` read, and mounts no editor infrastructure.
- `workspace/ProjectWorkspaceShell.isolation.test.tsx` and the other shell
  suites stay green (they mock `../views/Designer`, which `DesignerMode` still
  imports).
- Counts: `@seo/web` **615** tests / 60 files (was 611; +4 `DesignerMode`),
  `@seo/api` **1658** / 126 unchanged, `@seo/contracts` **483** unchanged.
  `pnpm typecheck`, `pnpm build` and `git diff --check` are clean.
  (One unrelated `Keywords.test.tsx` timeout was observed once under full-suite
  parallel load and passes in isolation; it does not touch this change.)

## 6. Known gaps deferred to later R5.5 milestones

- **Apply writes stored content, not the live document** (R5.5.2): after a
  successful server apply the live workspace document is unchanged until reload,
  and a dirty live document correctly disables apply via the revision guard.
  Routing the proposal through `applyExternalDocument` /
  `applyDocumentOperations` is R5.5.2.
- **Deep links** `/p/:id/workspace/designer/:contentId` do not open the document
  in designer mode (they never did); the workspace opens documents in editor
  mode. Revisiting this belongs with R5.5.3/R5.5.5.
- **Shared chrome** is still editor/composer only; Designer keeps its own
  `PageHeader` until R5.5.3.
- **Two run clients** (`useDesignerRun` vs `useEmbeddedAgent`) remain; converging
  them is R5.5.4.
- **Legacy `/p/:id/designer`** view is still mounted (R5.5.5).
