# R5.2.7 - Document-scoped workspace UI state

Status: **implemented** (part of the R5.2 batch).

This slice closes the R5.2 gap "One document-scoped workspace UI state" from
`docs/phase-5-roadmap.md`. It makes transient workspace UI state explicitly
scoped to the active document session boundary, so document B never inherits
document A's document-scoped view state. It does not add a UI state framework
and does not turn `DocumentSession` into a UI store.

## 1. The invariant

> Document-scoped workspace UI state MUST NOT silently carry over across a
> document identity boundary unless it is explicitly defined as
> workspace-global.

The boundary is the session's successful transition (`identity` +
`generation`), the same key R5.2.5 uses for editor history. A failed switch
(barrier blocked) does not cross it, so it never resets current state.

## 2. Scope classification

Every workspace state inventoried in the recon was classified. State that is
not document-scoped is deliberately left alone.

### document-scoped (reset on the session boundary)

| State | Owner | Why document-scoped |
| --- | --- | --- |
| `preview` | `EditorWorkspace` | Preview is a per-document reading view; B should not open in A's preview mode. |
| `railOpen` | `EditorWorkspace` | Visibility of the document tool rail is per-document view state. |
| `assistantOpen` | `EditorWorkspace` | The embedded Agent surface is opened against the active document. |
| `railTab` | `IntelligenceRail` | The active document side panel is document view state. |
| `sidebarMode` | `EditorShell` | Which insert/settings panel is active belongs to the open document. |

### workspace-global (must survive a document switch)

| State | Owner | Why workspace-global |
| --- | --- | --- |
| `useKnowledge` | `Content` | A user preference for including project knowledge in AI requests; not tied to one document. |

### editor-instance-scoped (owned elsewhere, not touched)

| State | Owner |
| --- | --- |
| undo/redo history, `canvasMode` | editor instance / `RichTextEditor` (R5.2.5) |
| `localSelection` fallback | `EditorSelectionContext` / `EditorShell` (R5.2.4) |

### ephemeral UI (transient, not document authority)

| State | Owner | Note |
| --- | --- | --- |
| `insertHint` | `EditorShell` | A transient "cannot insert" hint, cleared on the next interaction. |
| `CollapsibleSection.open` | `CollapsibleSection` | Disclosure of the secondary sections; not document-specific and not persisted. |
| `newTitle`, `notice`, `err` | `Content` | Form/notice state of the surrounding view. |
| `aiBusy`, `aiError`, `aiSuggestion`, `aiSelRange`, `aiEdit*`, `writerOpen` | `Content` | Document-scoped operation state that `resetAi()` already clears only after a successful switch. |

### operation/error state (kept distinct from the lifecycle)

AI errors and save failures remain outside both the document lifecycle and
this UI scope; they are not document-scoped view state.

## 3. The mechanism

A small workspace-level owner, not `DocumentSessionContext`:

```text
DocumentSession            Content passes documentScopeKey(identity, generation)
    identity/generation  -> WorkspaceStateProvider (workspace UI scope)
                                |
                                v
                            useDocumentScopedState(default)
```

- `session/useDocumentSession.ts` exports `documentScopeKey(identity,
  generation)`, the single document boundary key. `editorHistoryKey` delegates
  to it, so editor history and workspace UI scope share one epoch.
- `workspace/workspaceState.tsx` owns `WorkspaceStateProvider` (carries the
  boundary key) and `useDocumentScopedState`, which returns the default value
  whenever the carried key no longer matches the key the value was stored
  under. There is no reset effect and no remount: the state is keyed by the
  document boundary.
- `Content.tsx` wraps `EditorWorkspace` with
  `WorkspaceStateProvider documentKey={documentScopeKey(session.identity, session.generation)}`.
- Out-of-provider hosts (standalone `EditorShell` tests) fall back to a constant
  scope, so they are unaffected.

A stale setter captured under document A writes under A's key; because that key
no longer matches the active one, the value is never read back. A late A
transition therefore cannot reapply A's workspace state after B is active.

## 4. Why not a key/remount

R5.2.6 already unmounts `EditorWorkspace` while the next document loads, which
happens to reset this state. Relying on that is incidental and fragile. R5.2.7
makes the scope explicit and independent of the loading boundary, and proves it
with a probe that stays mounted across the switch (see tests). The editor
instance still uses a key, because that is a real instance boundary (R5.2.5).

## 5. What is not touched

No global UI state framework, no Redux/Zustand, no persistence, no per-document
UI preferences, no change to autosave/revision/selection/undo-redo/loading/save
barrier/persistence, no routes, no Composer/Designer integration. Selection
stays owned by `EditorSelectionContext`, history by the editor, the document
lifecycle by `DocumentSession`.

## Tests

`workspace/workspaceState.test.tsx` composes the real `useDocumentSession` and
the real `WorkspaceStateProvider`, with a probe that remains mounted across the
whole switch so it tests the keyed scope rather than a remount:

1. a successful switch resets document-scoped state to its default;
2. a failed switch preserves the current document's state;
3. a new document does not inherit the previous document's state;
4. closing the document drops the state (not authoritative for a future one);
5. reopening a document starts from fresh defaults (no accidental restoration);
6. workspace-global state survives a document switch while the scoped state resets;
7. a stale setter captured under the previous document cannot reapply its state
   once the next document is authoritative.
