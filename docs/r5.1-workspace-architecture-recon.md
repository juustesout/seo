## 1. Executive summary

The web app is a single React SPA with **no router library**. Routing is a
hand-rolled `window.history` + `popstate` implementation in
`apps/web/src/App.tsx` (`parseRoute` L87-94, `routePath` L97-100, listeners
L140-144). All project routes use the prefix `/p/:projectId/:view[/:sub]`
(`App.tsx:90`).

The three creative experiences the phase wants to unify are today three
independent pages with three different state models:

- **Composer** (`apps/web/src/views/Compose.tsx:73`) is **local-state only** and
  previews a plan/document; it persists exactly once, when the user creates a
  draft through `POST /projects/:id/content` (`Compose.tsx:144`).
- **Designer** (`apps/web/src/views/Designer.tsx:83`) owns a durable agent run
  (`components/designer/useDesignerRun.ts:74`), its own content list/detail
  fetch, and a server-side apply (`POST /content/:id/designer/apply`).
- **Editor** (`apps/web/src/views/Content.tsx:109`) owns the live Tiptap
  document, the autosave loop (`useAutosave` at `Content.tsx:245`), the document
  list, the read-only viewer, and the workspace shell
  (`components/content/workspace/EditorWorkspace.tsx:58`).

The single most important finding is a **hard blocker for mode switching**:
switching documents currently abandons pending autosave work, so unsaved
changes can be lost (`Content.tsx:209` + `318-357`, `useAutosave.ts:82-84`,
`EditorWorkspace.tsx:134`). R5.2's "one document, one save lifecycle" cannot be
built on top of the current ownership without fixing this first.

A second important finding is that the brief's proposed canonical path
`/projects/:projectId/workspace` does not match the app's established prefix
`/p/:projectId/...`. Introducing it would create two parallel project prefixes
used by links, tests and deep links. Section 4 records the deviation and the
recommendation.

Naming hazard: the components named `EditorWorkspace` and `EditorShell` already
exist and are **not** the phase-5 product shell (`EditorWorkspace.tsx:58` is the
R1 editor layout; `editor/EditorShell.tsx:11` is the composition canvas). The
phase-5 shell needs a distinct name, e.g. `WorkspaceShell`.

## 4. Target information architecture

### 4.1 Canonical route

Decision point: the brief proposes `/projects/:projectId/workspace`, but every
project route in the app is `/p/:projectId/:view` and every link/nav helper
writes `/p/...` (`App.tsx:98`, `lib/nav.ts:19`, `App.tsx:335-360`).

Recommendation: **keep the existing `/p/` prefix** and make the workspace a
project view with a mode sub-segment:

```
/p/:projectId/workspace            -> default mode (editor)
/p/:projectId/workspace/editor
/p/:projectId/workspace/composer
/p/:projectId/workspace/designer
```

This fits `parseRoute` unchanged (`view='workspace'`, `sub=<mode>`,
`App.tsx:90`) and avoids a second project prefix. If the product requirement is
literally `/projects/:projectId/workspace`, then `/projects/...` must be added
as the canonical prefix and `/p/...` kept as a redirect alias; that is a larger,
riskier change and is recorded here as an open decision (section 10).

### 4.2 Mode responsibilities

| Mode | Route sub | Responsibility | Primary existing code |
| --- | --- | --- | --- |
| Designer | `designer` | Visual direction, layout, sections, imagery, design decisions | `views/Designer.tsx` + `components/designer/*` + embedded agent |
| Composer | `composer` | Content structure, briefs, outlines, content planning | `views/Compose.tsx` + `composition/*` API |
| Editor | `editor` | Direct document editing and final content refinement | `views/Content.tsx` workspace branch + `components/content/**` |
| Preview | (not a mode yet; R5.7) | See the page as a page | `workspace/PreviewPane.tsx`, `CanonicalRenderer` |

Default mode when opening an existing document: **Editor** (R5.6 recommendation).

### 4.3 Target component structure

```
WorkspaceShell                         (new product shell; not EditorWorkspace)
|- WorkspaceHeader                     (project / page / save status; account chrome stays above)
|- ModeSwitcher                        (editor | composer | designer; no reload)
|- WorkspaceContext                    (project, role, active mode, document session)
`- ActiveMode
   |- EditorView    (current views/Content.tsx workspace branch)
   |- ComposerView  (current views/Compose.tsx)
   `- DesignerView  (current views/Designer.tsx)
```

Naming: `WorkspaceShell` must not collide with `EditorWorkspace`
(`EditorWorkspace.tsx:58`) or `EditorShell` (`editor/EditorShell.tsx:11`).
Consider renaming `EditorWorkspace` to `EditorView` during R5.6.

The shell owns navigation and identity; modes own their tools and panels.

| Concern | Owner | Notes / current source |

| Account chrome (`AppHeader`, sign-out) | App (unchanged, above the shell) | `App.tsx:387` |
| Mode tools/panels (plan tree, visual roles, editor toolbar/rail) | each mode | keep current internals initially |

must reuse `contentRevisionOf`, `canonicalFromEditorDocument`,
`editorDraftFromCanonical` and `useAutosave` rather than introducing a parallel
state framework.

## 8. Architectural conflicts and risks

Severity: **Blocker** blocks R5.2; **High** shapes the design; **Medium** cleanup.

1. **Blocker - unsaved changes are lost on document switch.**
   `workspaceReady` goes false immediately on `open()` (`Content.tsx:209`,
   `:318-326`), which makes `useAutosave` clear its timer and return
   (`useAutosave.ts:82-84`); `open`/`startNew`/`goList` never call `saveNow()`
   (`:318-357`); and `RichTextEditor` is remounted via `editorKey`
   (`EditorWorkspace.tsx:134`) with `loadSeq` bumped (`Content.tsx:325/346/356`).
   There is no `beforeunload`/flush guard. Mode switching that remounts the
   session would reproduce this across modes.

2. **High - `EditorContext` reads a lagging `doc` prop.**
   `EditorContextProvider` receives the React `doc` (`EditorWorkspace.tsx:112`),
   one render behind the live Tiptap document. Its guards compare against that
   prop (`EditorContext.tsx:129/153/163/168`), so an immediate post-edit apply
   can return a false `stale-revision`.

3. **High - route prefix mismatch with the brief.**
   Brief says `/projects/:id/workspace`; app uses `/p/:id/...`. Resolving this
   changes nav, tests and deep links (section 4.1).

4. **High - two parallel Designer engines over the same endpoints.**
   `useDesignerRun` (`components/designer/useDesignerRun.ts:74`) and
   `useEmbeddedAgent` (`workspace/useEmbeddedAgent.ts:84`) both POST
   `/designer/runs` and GET `/designer/runs/:id`, each re-implementing epoch
   guards, polling and outcome mapping (`embeddedAgent.ts:408` vs
   `Designer.tsx:123-130`).

5. **High - apply capabilities are split.**
   `DesignerService.apply` refuses `insertion`/`operations`/`acquisition`
   (`designerService.ts:441-461`), so the standalone Designer can only apply
   plain document proposals, while the embedded editor agent applies
   insertion/operation batches client-side (`EditorContext.tsx:149-198`).

6. **High - three write paths into `seo_content`.**
   Compose create (`Compose.tsx:144`), editor autosave PATCH/POST
   (`Content.tsx:235-236`), Designer apply (`Designer.tsx:178`), plus the
   `/draft` path (`content.ts:179`). All reach `ContentService.write`
   (`contentService.ts:200`) with different client-side guards.

7. **Medium - three selection owners.** `EditorSelectionContext.tsx:26`,
   `EditorContext.tsx:101`, and `Content.tsx:306-316` (`hasSelection`). Coarse
   `EditorSelection.path` is explicitly non-durable (`editor/types.ts:6-8`).

8. **Medium - three composition representations.** Plan tree
   (`Compose.tsx:284`), canonical document, and Tiptap nodes
   (`editor/CompositionNodes.ts:99-138`), bridged at `editorDraft.ts:42`.

9. **Medium - three preview entry points** (`Compose.tsx:249`,
   `Designer.tsx:502/512/633`, `workspace/PreviewPane.tsx:15`), two needing the
   editor bridge.

10. **Medium - workspace UI state not keyed to the document.**
    `preview`/`railOpen`/`assistantOpen` (`EditorWorkspace.tsx:72-74`) and
    `EditorSelectionContext` state (`:26`) survive a document change, so stale
    selection/reveal/agent state can leak onto the next document.

11. **Medium - duplicate document list/detail fetches.**
    `Content.tsx:129/172` and `Designer.tsx:112/117` fetch the same endpoints
    with separate selection and stale-response handling.

12. **Medium - no router library.** No 404, no guards, no canonicalization;
    unknown paths silently fall back to `Overview` (`App.tsx:92`) and unknown
    project views render an empty main (`:311-331`).

13. **Medium - duplicated client role gating.** `ROLE_RANK` re-declared in
    `Compose.tsx:44`, `Designer.tsx:36`, `Content.tsx:79`, mirroring server
    `requireRole` gates.

14. **Low - dead and duplicated routes.** `views/Data.tsx` dead; `/` vs
    `/overview`; `/p/:id` vs `/p/:id/dashboard`; account `/compose` silently
    uses `me.projects[0]`.

15. **Low - two header layers.** `AppHeader` (`App.tsx:387`) plus per-view
    `DocumentHeader`/`PageHeader`; the workspace header must sit inside the
    account chrome without duplicating save state (currently only the editor
    has a save indicator).

## 9. Recommended implementation sequence for R5.2

R5.2 is "unified document and session state". Do it as small, verifiable slices.
Each slice must keep the existing editor tests green.

1. **Session extraction (pure refactor).** Move document identity, `doc`,
   metadata, baseline, revision and `useAutosave` out of `views/Content.tsx`
   into a `WorkspaceDocumentSession` provider (new file). Keep external rendered
   output identical. Reuse `contentRevisionOf`, `canonicalFromEditorDocument`,
   `editorDraftFromCanonical`.
2. **Provider lift.** Move `EditorContextProvider` and `EditorSelectionProvider`
   from `EditorWorkspace.tsx:107-115` up to the session owner so Composer and
   Designer can read the same live document and selection.
3. **Fix the stale-doc seam.** Make `EditorContext` read the live editor/ref
   rather than the lagging `doc` prop (conflict 2), so revision guards are
   exact.
4. **Flush guarantees.** On content/document change and on unmount, await
   `saveNow()` (and guard `beforeunload`) before flipping `enabled` false
   (conflict 1). Add tests for "switch document with pending edits".
5. **Single revision/dirty model.** Replace the two equality systems (autosave
   snapshot string vs `contentRevisionOf`) with one documented rule; reconcile
   metadata-only changes.
6. **Workspace route + shell scaffold (enables R5.3).** Add
   `/p/:id/workspace[/:mode]`, mount the session, add `ModeSwitcher` with local
   mode state and URL sync via `history.replaceState` (no reload). Add legacy
   aliases as redirects only for modes that already work end-to-end.
7. **Mount Editor mode first** (default), then Designer, then Composer, each
   consuming the shared session. Keep capability integration in R5.4-R5.6;
   R5.2 only needs the shared state to be real for Editor.

Review gate after slice 4: switching documents and modes never loses unsaved
changes. Review gate after slice 7: one route, one document state, modes switch
with no reload and no competing save.
