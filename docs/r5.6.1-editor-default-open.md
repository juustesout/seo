# R5.6.1 - Editor default-open behavior (product decision + closeout)

Status: **closed as a product decision + verification**. Documentation only. No
code, contracts, routes, migrations, or tests were changed, because the existing
implementation already satisfies the decision.

## 1. Decision

For the unified workspace editor route:

- `/p/:projectId/workspace/editor` **without** a `contentId` -> keep showing the
  existing Content Studio **document picker** (the content list). This is the
  calm, predictable landing for the user.
- `/p/:projectId/workspace/editor/:contentId` **with** a `contentId` -> open
  that document directly.
- **No new persistence** (no "last opened document"), **no auto-open**, **no
  auto-create**, **no second document-selection mechanism**.
- The shared `DocumentSession` remains the single owner of document identity; the
  existing picker remains the user entry point.

Rationale: the picker already works and the user prefers it. Introducing a
"last document" concept would add a second, implicit selection mechanism that the
architecture does not have today (`docs/r5.6.0-editor-integration-recon.md`
section 4).

## 2. Current behavior (verified in the repository)

| Route | Behavior | Evidence |
| --- | --- | --- |
| `/p/:id/workspace` | `sub=null` -> `normalizeWorkspaceMode(null) = 'editor'` | `App.tsx:287-289`; `WorkspaceModeSwitcher.tsx:26-28` |
| `/p/:id/workspace/editor` | `sub2=null` -> `initialContentId=null` -> session stays `idle` -> `EditorView` renders the content list/picker | `App.tsx:289,327`; `useDocumentSession.ts:90`; `EditorView.tsx:334-429` |
| `/p/:id/workspace/editor/:contentId` | `sub2` -> `initialContentId` -> one-shot `open(id)` | `App.tsx:289,327`; `EditorView.tsx:213-218` |
| `/p/:id/content[/:contentId]` | Redirects to the canonical workspace route, preserving the document id as `sub2` for `content` | `projectRoute.ts:53-55`; `App.tsx:149-162` |

Supporting facts:

- **No last-opened persistence.** The only `localStorage` uses in the web app are
  the Designer run bookmark and the Writer run bookmark
  (`workspace/designerRunClient.ts:10,34-56`; `WriterPanel.tsx:292,355`).
- **No auto-create.** `startNew` calls `requestNewDocument` with
  `creating=true`; a row is created only on the first autosave
  (`ProjectWorkspaceShell.tsx:209-215`; `useDocumentSession.ts:181`;
  `workspaceSession.tsx:160-188`).
- **No implicit selection.** There is no "open first/last/most-recent" code path;
  the only two ways a document becomes active are `open(id)` from the picker/deep
  link and `startNew()` (`ProjectWorkspaceShell.tsx:205-215`).
- **One identity owner.** `useDocumentSession` owns `identity`/`generation`/
  `boundary`; the picker only requests a switch through it
  (`useDocumentSession.ts:138-201`).
- **Empty project.** With no documents the picker is replaced by an `Empty`
  message; nothing is auto-opened (`EditorView.tsx:379-381`).

## 3. Non-goals (explicit)

- No "resume last document" or "open most recent" behavior.
- No new `localStorage`/`sessionStorage` document key.
- No change to the shared session, loader, lifecycle, autosave, revision, or
  mutation bridge.
- No new document-selection surface alongside the picker.

## 4. Acceptance criteria

1. `/p/:id/workspace/editor` (no `contentId`) shows the existing Content Studio
   picker and does not open, create, or fetch a specific document.
2. `/p/:id/workspace/editor/:contentId` opens that document through the shared
   session.
3. No document id is persisted across sessions.
4. The shared `DocumentSession` remains the only identity owner.

All four hold today; no implementation was required.
