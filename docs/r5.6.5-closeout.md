## 1. Status

The Editor is genuinely embedded in the unified workspace. There is one
document session, one autosave, one revision contract, one selection owner, one
editor instance and one mutation bridge. R5.6 simplified the editor's chrome and
contextual surfaces and hardened their integration without adding a second
identity, session, loader, autosave, revision, selection, route, or contract.

No concrete R5.6-attributable defect was found in R5.6.4 or this close-out.

## 2. Delivered areas (A)

For each area: responsibility / canonical owner / invariant / integration seam /
verification.

**2.1 Editor mode boundary.** `EditorMode` owns all editor infrastructure
(Tiptap-adjacent state, `EditorSelectionProvider`, `EditorContextProvider`,
keymap, editor AI availability, assistant entry), so Composer/Designer never
mount it. Owner: `apps/web/src/workspace/EditorMode.tsx:131-132`.
Invariant: exactly one editor infrastructure per active editor mode.
Seam: shell mode dispatch. Verified by
`ProjectWorkspaceShell.isolation.test.tsx` (mounts/spies on the providers).

**2.2 Toolbar and chrome simplification (R5.6.2).** `ContentToolbar` keeps only
bold/italic/undo/redo persistent and folds every block/structural command into a
single `Format` disclosure; the on-demand **Tools** toggle in `DocumentHeader`
opens the intelligence rail. Owner: `ContentToolbar.tsx`,
`workspace/DocumentHeader.tsx:114-148`, plumbed shell -> `EditorMode` ->
`EditorView` -> `EditorWorkspace`. Invariant: no command removed; canvas
dominates by default; canvas controls hidden outside editor mode.
Seam: shell document-scoped `toolsOpen`. Verified by `ContentToolbar.test.tsx`,
`DocumentHeader.test.tsx`, `ProjectWorkspaceShell.chrome.test.tsx`,
`WorkspaceChrome.test.tsx`, `EditorWorkspace.test.tsx`.

**2.3 Contextual intelligence rail (R5.6.3).** `IntelligenceRail` is the
on-demand segmented surface (Outline/SEO/Media/Insights). `SeoPanel` surfaces the
existing `SeoResult.stats` and promotes non-pass `suggestion` inline; the outline
target skips empty headings and places the caret inside the heading; the
Insights panel is keyed by document identity. Owner:
`workspace/IntelligenceRail.tsx`, `SeoPanel.tsx`,
`RichTextEditor.tsx:75-97`. Invariant: no new metric; no stale per-document
context. Seam: `EditorContext`/selection, `session.boundary`. Verified by
`IntelligenceRail.test.tsx`, `SeoPanel.test.tsx`, `ContentOutline.test.tsx`.

**2.4 Document session ownership.** `useWorkspaceSession` hosts the one
`useDocumentSession`, one `useDocumentLoad`, one lifecycle projection and one
`useAutosave`. Owner: `apps/web/src/workspace/workspaceSession.tsx:124,190`.
Invariant: a single identity/epoch/revision owner. Seam: all modes read it via
`useWorkspaceSessionContext`. Verified by grep (single call site of
`useDocumentSession(` and `useAutosave(`) and session tests.

**2.5 Mutation bridge.** `CompositionApplyBridge` stages Composer/Designer output
as the existing `DesignerProposal` and applies it through
`applyExternalDocument`/`applyDocumentOperations`/`applyImageInsertion`, guarded
by `session.boundary`, `targetDocumentId` and `baseRevision`. Owner:
`workspace/CompositionApplyBridge.tsx:150-187`. Invariant: one editor mutation
path; a moved boundary/foreign document/stale revision is a no-op.
Seam: `EditorContext.setContent`
(`editor/EditorContext.tsx:140,186`). Verified by
`CompositionApplyBridge.test.tsx` (17), `.composerApply`, `.designerApply`.

**2.6 Default-open behavior (R5.6.1).** `/workspace/editor` (no id) shows the
picker; `/workspace/editor/:id` opens that document; no last-opened
persistence/auto-open/auto-create. Owner: route + `EditorView.initialContentId`
one-shot (`views/EditorView.tsx:213-221`). Invariant: the picker is the only
user entry; `DocumentSession` remains the sole identity owner. Verified by
`docs/r5.6.1-editor-default-open.md` and route/editor tests.

## 3. Session integration verification (B)

Repository evidence: `components/content/session/useDocumentSession.ts`,
`workspace/workspaceSession.tsx`.

| Check | Result | Evidence |
| --- | --- | --- |
| One canonical document identity | Yes | `identity`/`generation`/`boundary` only in `useDocumentSession`; single call site `workspaceSession.tsx:124` |
| Switching goes through the session lifecycle | Yes | `requestDocumentSwitch`/`requestNewDocument`/`requestCloseDocument` -> `runBarrier` (`useDocumentSession.ts:151-184`) |
| Switching respects the save barrier | Yes | `runBarrier` awaits `flush`; blocked keeps the current document authoritative (`:152-167`); tests: `workspaceState.test.tsx`, `undoRedoBoundary.test.tsx` case 4 |
| Stale document state cannot become active | Yes | loader keyed by id; `documentLifecycle` trusts loader state only when it matches identity (`useDocumentSession.ts:64-78`); `useDocumentLoad` clears on switch |
| Lifecycle coherence loading/error/ready | Yes | pure projection `documentLifecycle`; `EditorView` renders explicit idle/loading/error/ready branches (`EditorView.tsx:337-463`) |
| Generation/history scoping preserved | Yes | `editorHistoryKey` = `documentScopeKey(identity,generation)`; editor keyed by `session.boundary` (`EditorWorkspace.tsx:99`); `undoRedoBoundary.test.tsx` |
| Document-scoped UI does not leak | Yes | `WorkspaceStateProvider documentKey={boundary}` (`ProjectWorkspaceShell.tsx:72`) + `useDocumentScopedState` (stale setter cannot write to a live scope) |

First-save id adoption changes the persistent identity without moving the
boundary/generation (`adoptDocumentId`, `useDocumentSession.ts:192`), so the
editor instance, its history and document-scoped UI state are preserved.

No competing state ownership was found. The published ownership table in the
R5.6.0 recon (section 5) still holds against the current tree.

## 5. Cross-mode integration (D)

- Composer/Designer read the shared session read-only and stage mutations as the
  existing `DesignerProposal`; the shell stays mounted across the mode change, so
  the staged value survives and is applied once the editor remounts.
- The apply is bound to the same active document: `session.boundary` and (for
  Designer) `targetDocumentId` plus `baseRevision` are re-checked at apply time
  (`CompositionApplyBridge.tsx:162-174`). No document switch and no `/content`
  create occurs on apply.
- The embedded agent, when the editor is active, applies directly through
  `EditorContext` (no bridge), which is correct because no mode change is
  involved.
- Navigator hold: an open Composer/Designer review blocks a mode switch until
  cancelled or applied (`ProjectWorkspaceShell.tsx:171-186`), so a review cannot
  be silently discarded.

No competing document identity or stale editor state is created across modes.

## 7. Known limitations

Only actual, already-recorded limitations:

- **G7 - selection reset key.** `EditorSelectionProvider` clears selection on
  `documentId` (`EditorSelectionContext.tsx:56-58`) rather than `boundary`, so a
  first-save id adoption clears the canonical selection once. Transient and
  self-healing (the next selection event re-derives it). Recorded, not scheduled.
- **On-demand rail tab reset.** Closing and reopening the Tools surface resets
  the rail to Outline. Expected for an on-demand surface; no user state set for
  the current document is lost.
- **`popstate` back/forward.** Route identity sync does not special-case
  back/forward. Pre-existing routing limitation, out of R5.6 scope.
- **G5 - `EditorToolbar` unused in the workspace path.** `EditorWorkspace`
  always passes an explicit toolbar, so `EditorMain`'s default `EditorToolbar`
  is not rendered in the workspace (still used/tested standalone). Harmless
  redundancy, deliberately not refactored here.
- **`viewport` chunk size.** The production web build reports a >500 kB chunk
  warning. Unrelated to R5.6; noted for a future performance pass.

## 9. Handoff

Ready for the next roadmap phase:

- The Editor is the default mode for an existing document
  (`normalizeWorkspaceMode(null) = 'editor'`), with the picker as the stable
  no-id landing and direct deep-link open for the rest.
- One shared document session (identity/epoch/loader/lifecycle/autosave/
  revision) and one mutation bridge are the seams every mode consumes; R5.7/R5.8
  build on them rather than beside them.
- Preview already exists as an in-editor pane (`PreviewPane`, canonical render
  with an honest fallback). **R5.7** owns the deeper preview/responsive
  experience (desktop/mobile, canvas-vs-page boundary); R5.6 wired the toggle
  and the render, not the strategy.
- **R5.8** owns the broader contextual-UI program. R5.6 made the rail on-demand
  and contextual to the document (Outline/SEO/Media/Insights) but did not build
  a selection-driven contextual system.
- Deferred items previously recorded remain deferred: idempotency key +
  bookmark/reconnect policy (R5.5.4b), `popstate` handling, `DesignPackage`
  runtime integration, and the media-provenance migration runtime check. These
  are outside R5.6's scope and are not expanded here.
